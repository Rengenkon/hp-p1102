# Проверка проекта

[Краткая инструкция](../README.md)

Все команды выполняются из корня репозитория.

## Модульные и HTTP/IPP-тесты

Без root и USB; сторонние зависимости устанавливаются только в `.venv`:

```bash
python3 -m venv .venv
.venv/bin/python -m pip install --require-hashes -r requirements-proxy.lock
.venv/bin/python -m unittest discover -s tests -v
```

Проверяются восстановление очереди, ошибки CLI, работа с терминалом/sudo,
IPP-кодек и прокси. HTTP-тесты используют имитацию CUPS и проверяют неизменность
бинарного документа при chunked-передаче. Без зависимостей прокси соответствующие
тесты пропускаются; для полной проверки используйте виртуальное окружение.

## Docker-интеграция: локальный образ

Нужен собранный локальный образ; его тег выводит команда `deploy`.

```bash
python3 tests/smoke_container.py local/hplip-p1102:local-<хеш-из-вывода-сборки>
```

Проверяются запуск, повторное применение, восстановление URI/параметров,
атомарная замена конфигурации, реальное IPP-подключение с `everywhere` и SIGTERM.
Тестовый backend записывает UID/GID и проверяет фактическую основную группу
процесса CUPS, а не только членство `lp` в `/etc/group`.

## Docker-интеграция: серверный образ

Нужен собранный серверный образ; его тег выводит команда `server`.

```bash
python3 tests/smoke_server.py local/hplip-p1102:server-<хеш-из-вывода-сборки>
```

Проверяются корневой URI, статус/отмена, Print-Job, Create-Job/Send-Document,
рендеринг в тестовый backend и печать из отдельного CUPS-клиента, подключенного
к `ipp://сервер:8631` с драйвером `everywhere`.

Оба сценария создают временные контейнеры, сеть и конфигурацию, затем очищают их.
Физический USB не подключается, хостовые настройки не меняются, бумага не расходуется.
Общие функции запуска Docker, ожидания готовности и очистки находятся в
`tests/docker_helpers.py`.

## Физическая проверка и платформы

```bash
python3 scripts/printer.py test-print
```

Команда печатает через текущий режим. Подтвердите выход страницы отдельно;
для проверки сети отправьте документ с клиентского компьютера.

Сборки и Docker-проверки выполнены на `amd64`. `arm64` и пакетные/сервисные
адаптеры других дистрибутивов требуют проверки на соответствующих хостах.
