# Диагностика и восстановление

[Краткая инструкция](../README.md)

## Команды и журналы

```bash
python3 scripts/printer.py status
python3 scripts/printer.py doctor
python3 scripts/printer.py server --verbose
docker compose --env-file .state/compose.env logs --tail=100 hplip
```

`status` и `doctor` не меняют системные настройки. Каждый этап обозначается
номером, действия — `OK`, `SKIP`, `CHANGE`, `FIX`, `WARN`. Ошибка содержит этап,
вывод неудачной команды, выполненные этапы и дальнейшие действия.
Журналы — `.state/logs/`; traceback показывается с `--verbose`.
Операции имеют тайм-ауты. Код завершения `0` означает успех, ненулевой — ошибку.

## Клиент не подключается

Укажите IP компьютера с принтером, а не адрес маршрутизатора. С клиента проверьте:

```bash
curl --connect-timeout 5 http://<адрес-сервера>:8631/health
```

Ожидается `OK`. Убедитесь, что выбран режим `server` и клиент может достичь
сервера по сети. `localhost` подходит только на самом компьютере с контейнером.
Сетевые правила и firewall настраиваются отдельно.

## Задание принято, но бумаги нет

```bash
python3 scripts/printer.py doctor
```

Проверьте подключение принтера и журнал backend. При `open device failed stat=12`
проверьте режим USB-узла `0660` и соответствие основной группы CUPS USB-группе.
`doctor` пробует открыть USB с учетными данными CUPS и показывает UID/GID/Groups
работающих HP backend из `/proc`. После переподключения путь
`/dev/bus/usb/BBB/DDD` меняется — это нормально.

Если Unix-права верны, проверьте локальные запреты SELinux/AppArmor.
Скрипт не отключает политики безопасности автоматически.

`test-print` отправляет реальное задание, но выход страницы нужно подтвердить
отдельно. Без подключенного принтера развертывание допускается с предупреждением.

## Повторное применение конфигурации

Повторите команду выбранного режима: `deploy` или `server`.

- Существующая USB-группа используется с фактическим GID; правило udev обновляется
  при отличии и проверяется для конкретного устройства.
- Верный плагин не скачивается повторно; неверный архив не исполняется.
- Готовый образ используется повторно; исправный неизменный контейнер сохраняется.
- Очередь сверяется с URI, драйвером и параметрами; задания не удаляются.
- Поврежденный PPD восстанавливается, отсутствующая очередь создается.
- Отключенная очередь включается. Если она снова останавливается, исследуйте журнал.
- Удаленные из TOML управляемые параметры снимаются; прочие параметры и очереди сохраняются.
- Параллельные команды из одного репозитория блокируются.

Обновление образа или параметров запуска может пересоздать контейнер. При неудачной
смене режима автоматического отката нет. Для возврата выполните команду прежнего режима.
Не используйте `docker compose down -v`, если не намерены удалить настройки и задания.
