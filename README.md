# HP LaserJet P1102: конфигурация как код

CUPS, HPLIP и HP-плагин для конкретного USB-принтера HP LaserJet Professional
P1102 работают в закрепленном Docker-образе. Идентификаторы устройства и параметры
печати заданы в `printer.toml`; по умолчанию используется A4.

## Требования

На Linux-компьютере, к которому подключен принтер, нужны:

- Python **3.11+**;
- локальный **rootful Docker Engine**, доступный текущему пользователю;
- Docker Compose с поддержкой `up --wait` (v2.20+ или новее);
- udev/eudev, `install`, `mv`, `sha256sum` и средства создания групп;
- `sudo` для настройки хоста, если команда запускается не от root.

Команда развертывания использует стандартную библиотеку Python. Зависимости
серверного прокси установлены в виртуальном окружении внутри Docker.
HP-плагин — проприетарное ПО; запуск развертывания предполагает принятие его лицензии.

## Локальная печать

```bash
python3 scripts/printer.py deploy
```

Команда проверяет хост и плагин, настраивает USB-права, собирает образ, запускает
контейнер и регистрирует очередь в CUPS хоста для печати из приложений.
Если CUPS отсутствует, возможна автоматическая установка согласно
`host.install_cups` в `printer.toml`.

Контейнер: **`hp-p1102-local`**. IPP доступен на loopback:

```text
ipp://localhost:8631/printers/HP_LaserJet_Professional_P1102
```

## Сервер печати

На компьютере с USB-принтером:

```bash
python3 scripts/printer.py server
```

Команда настраивает USB и запускает CUPS с IPP-прокси внутри контейнера.
Пакеты и очередь CUPS на хосте не устанавливаются. `sudo` нужен для необходимых
изменений USB-группы и правила udev.

Контейнер: **`hp-p1102-server`**. Порт опубликован на `0.0.0.0:8631`.
На клиенте укажите IP компьютера с принтером:

```text
ipp://<адрес-сервера>:8631
```

На Linux-клиенте с работающим CUPS:

```bash
sudo lpadmin -p home_print -E -v ipp://<адрес-сервера>:8631 -m everywhere
lp -d home_print document.pdf
```

Проверка доступности и удаление клиентской очереди:

```bash
curl --connect-timeout 5 http://<адрес-сервера>:8631/health
sudo lpadmin -x home_print
```

Ответ проверки — `OK`. Адресацию и firewall настройте средствами своей сети.

## Переключение и повторный запуск

`deploy` и `server` управляют одним Compose-сервисом. При смене режима прежний
контейнер заменяется новым; тома CUPS, настройки и задания сохраняются.
Повторная команда того же режима сохраняет исправный контейнер и применяет
изменения конфигурации. Автоматического отката при неудачной смене режима нет.

Контейнер работает в фоне и запускается после перезагрузки через
`restart: unless-stopped`. Выбранный режим сохранен в `.state/compose.env`.
Для возврата к локальной печати выполните `deploy`.

## Проверка и диагностика

```bash
python3 scripts/printer.py status
python3 scripts/printer.py doctor
python3 scripts/printer.py test-print
```

`test-print` отправляет страницу на физический принтер: через очередь хоста
в локальном режиме или через IPP-прокси в серверном. Прием задания не подтверждает
выход бумаги. Запуск на сервере через `localhost` не проверяет сеть до клиента.
Развертывание само ничего не печатает; без USB-принтера оно продолжается с предупреждением.

Подробные журналы находятся в `.state/logs/`. Для расширенного вывода добавьте
`--verbose` к команде. Журнал контейнера:

```bash
docker compose --env-file .state/compose.env logs --tail=100 hplip
```
